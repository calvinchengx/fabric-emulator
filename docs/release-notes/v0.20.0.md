# v0.20.0

A security release. Twelve commits, and the theme is **what the emulator will
do on a stranger's say-so**: it used to send a Key Vault bearer token to any
host a connection named, and mirror a lakehouse listing to any path the
listing chose. Both are now bounded, with the boundary tested rather than
asserted.

This is also the release where CodeQL and Dependabot arrive — the last repo in
the family without them. Their first run is what surfaced everything below.

**One behaviour change needs configuration: see Upgrading.**

---

## The vault token goes only to a vault

Resolving an `AzureKeyVaultReference` mints a workspace-identity bearer for
`https://vault.azure.net` and sends it to `credentials.vaultURI` — a value
taken straight from the request body. A hostile URI therefore exfiltrated the
token, and doubled the emulator as an SSRF probe into whatever its process
could reach (sibling containers, cloud instance metadata, the host).

`vaultURI` is now checked before anything is dialled: Azure's vault domains
(`*.vault.azure.net` and the China, US Gov, Germany and Managed HSM
equivalents) over HTTPS, or one configured emulator host. Everything else is
refused with the Fabric-shaped `TestConnectionFailed`.

The tests name the attacks rather than the happy path: cloud metadata at
`169.254.169.254`, the emulator's own API, suffix smuggling
(`contoso.vault.azure.net.evil.com`), userinfo disguise
(`…vault.azure.net@evil.com`), the bare suffix with no vault label, right host
with the wrong port, and cleartext to a real vault.

This also **closes a parity gap**: real Fabric will not resolve an AKV
reference to an arbitrary URI either, so the permissive version was less
faithful, not more capable.

## The lakehouse mirror stays inside the mount

`/mount` mirrors a lakehouse's `Files/` to `/lakehouse/default/Files`, deriving
each local path from the remote listing. A lakehouse entry named `../../…`
walked `os.path.join` out of the mount, and the writer overwrote files on the
container disk. Real Fabric FUSE-mounts the lakehouse and cannot be escaped
this way.

Containment is now decided after `realpath` — so a symlink already inside the
tree is not a way out either — and compared with `commonpath` rather than a
string prefix, because `/lakehouse/default/Files-evil` starts with the mount
root as text while being a different directory. Refused entries are counted
and logged, not silently skipped.

Proven end to end: the real `sync()` is driven against a listing full of `..`
entries and asserted to write nothing outside the mount. Reverting the guard
fails those tests, which is the point of having them.

## Least privilege in CI

Every job in `ci.yml`, `spark-jvm.yml`, `xmla.yml`, `real-fabric.yml` and
`pbix-desktop.yml` now runs with `contents: read` rather than inheriting the
repository default — 51 CodeQL findings, fixed as five top-level declarations
after confirming no job needs a write scope. A job that later needs more
should declare it at the job level, where the elevation is visible.

## CodeQL and Dependabot

Scanning Go, JavaScript/TypeScript, **Python** and Actions. Python is included
here unlike in the sibling repos, because `python/` is a shipped first-party
package (the notebookutils shim) rather than a test driver; C# stays out, being
external probe harnesses. Dependency updates are grouped by ecosystem — gomod,
npm, uv, docker, actions — because this repo's surface would otherwise open a
dozen PRs a week and drown the signal.

Two findings were dismissed with reasons recorded on the alerts: an
`unsafe-quoting` report on the Spark statement builder, where `json.Marshal`
into `json.loads` *is* the escaping, and `InsecureSkipVerify` in the
`healthcheck` subcommand, which probes its own self-signed cert on localhost.

## Upgrading

**If you use `AzureKeyVaultReference` connections against a non-Azure vault —
including the family's `keyvault-emulator` — set the host that is allowed:**

```
FABRIC_AKV_VAULT_HOST=keyvault-emulator:8444
```

Both compose files here already declare it. Without it, a reference to that
vault is refused at connection create with `TestConnectionFailed`; references
to real `*.vault.azure.net` vaults need no configuration and are unaffected.

Nothing else changes.
