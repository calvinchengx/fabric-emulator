# v0.38.0

The range starts at `230d29d3` (#495), the first commit after the `v0.37.0`
tag, and ends at `7c79544c` (#504): 7 changes.

The headline is **a second kind of evidence**. Every claim in
`docs/witnesses.json` rested on a client: something Microsoft ships drives a
surface and its own model rejects a wrong shape. That is strong and it is
narrow — fifteen claims had no client witness at all, because no packaged
client speaks those surfaces, so the implementation and the expectation behind
them were written by the same hand. This release adds a machine-readable
oracle that is Microsoft's: their published OpenAPI, validated against
responses the emulator really gave.

**It found seventeen disagreements and sixteen are fixed.** Every one was on a
surface that already passed a client witness, because a driver asserts on the
fields it uses and never looks at the rest.

**Read Upgrading before you bump.** Five response shapes change, each toward
what Microsoft documents, and two of them will break a consumer that parses
the old shape.

---

## Responses are validated against Microsoft's own schema (#500)

`FABRIC_RECORD_RESPONSES` makes the emulator append the method, path, status
and body of each documented-surface response. No headers, ever — the
Authorization header carries a bearer token and the recording is uploaded as a
CI artifact, which a test asserts rather than trusts. Six e2e suites record;
the traffic already existed and was being discarded.

`scripts/check_openapi_conformance.py` validates that recording against
`third_party/fabric-rest-api-specs` (Microsoft's, MIT, 55 swagger files) and
`third_party/powerbi-rest-swagger` — **1016 documented routes**. The Power BI
spec had been vendored here since the `executeQueries` work as a "golden
reference" and had only ever been READ: quoted in Go comments, never compared
against a response. It is executed against now.

**What a pass means: shape, never semantics.** A job reported `Succeeded` that
ran nothing is perfectly conformant. This says the answer was SHAPED right,
not that it was true — the client witnesses remain the evidence for the rest.

### The sixteen fixes

**Deployment pipelines answered without most of what the spec requires.**
Create returned the pipeline without the `stages` it had just created. An
operation reported neither `type`, `status` nor `lastUpdatedTime`, all three
required and all three derivable — the kind is the only kind recorded, the
status is terminal because the row is written once the deploy has finished,
and the timestamp was already the row's `created_at`. `performedBy` was a bare
id where the spec has a principal object, and `note` a bare string where it is
an object with room for `isTruncated`.

**`git/status` omitted `conflictType`**, which the spec marks required and
gives a `None` member precisely so the ordinary case has a value.

**Warehouse properties omitted `createdDate` and `lastUpdatedTime`.**
`lastUpdatedTime` reports the CREATION time, and that limitation is in the
code rather than hidden: the items table carries `created_at` and nothing
else, so this emulator does not know when an item last changed, and a caller
diffing the two fields to detect an edit will not see one. The alternative was
continuing to omit a required field.

**An unrouted `/v1.0/myorg` path answered HTML (#497).** The guard that keeps
the operator portal off API paths already existed — written after Azure
PowerShell died on HTML with *"Unexpected character encountered while parsing
value: <"* — and its prefix list covered `/v1` but not the Power BI roots. So
`Get-PowerBIReport` reported *"Unable to deserialize the response"*, which
reads like a serialisation bug in the reports surface rather than a route that
does not exist. The shape is measured, not assumed: the real service answers
an unrouted path with ASP.NET's `{"Message":"No HTTP resource was found…"}`,
which is not Fabric's envelope, so `/v1` keeps its own.

**Domain roles: Microsoft contradicts itself on one page (#504).**
`role-assignments-bulk-assign` gives a `DomainRole` enumeration of `Admin` and
`Contributor`, and its own worked examples immediately below post `Admins` and
`Contributors`. The swagger agrees with the enumeration; this emulator was
written from the examples, so it accepted only the plural and reported it
back. Which the service accepts cannot be settled without a tenant, so BOTH
documented spellings are accepted and the schema's form is stored and
reported. A third is still refused.

### The one that is pinned rather than fixed

`microsoftEntraMembers` answers without `tenantId`, which the spec marks
required. This is not the emulator inventing a shape: OneLake roles are stored
as the raw body the caller PUT and echoed back, so it is a fixture's omission
reflected. The faithful fix is to REFUSE a member without one at authoring
time, which is a behaviour change across several fixtures and wants its own
argument.

## Route coverage, and a ratchet (#500, #504)

Conformance validates the responses a suite happened to produce and is silent
about the routes no suite touches — where a wrong shape lives longest, because
nobody is looking. `scripts/check_route_coverage.py` measures which of the
routes the emulator registers have been exercised, and holds the result to
`docs/route-coverage.json`.

**77 of 133 in-scope routes, up from 19 when it was written.** The gate is not
"all 133": the honest denominator is what this emulator serves, not the 1016
Microsoft documents, and a gate nobody can pass is a gate somebody deletes. It
is that the number cannot get worse — a new route with no traffic fails, a
route that stops being exercised fails, and a route that STARTS being
exercised also fails, because the file records what is not yet proved and an
improvement that leaves it unchanged leaves a lie in it.

The nine `admin/domains` routes were the largest uncovered cluster and are now
all exercised (#504).

## Typed clients where there were transports (#496, #499)

`az rest` is a TRANSPORT: it sends the URL the script wrote and returns the
body, carrying no model of anything. Eighteen claims rested on it alone.

**MicrosoftPowerBIMgmt** (#496) — Microsoft's own PowerShell module, driven
with nothing reconfigured: its stock `Public` environment resolves to
`api.powerbi.com` and `login.microsoftonline.com`, and the emulator answers at
both. Wiring it up found three defects no existing witness could reach.
Global-service discovery was unimplemented, so the module could not connect at
all — and the oracle there is the CLIENT, because the public endpoint 404s and
the shape had to come from Microsoft's shipped assemblies. `api.powerbi.com`
was missing from the TLS certificate although the emulator has served that
alias for releases, failing every client that validates.

**`fab`'s typed verbs** (#499) — `job run-sch`, `job run-list`, `acl`,
`label set/rm` and `mkdir` of a Domain or ManagedIdentity build the request
body, choose the route and parse the reply themselves, unlike the `fab api`
passthrough. `ci:fabric-cli` goes from 3 claims to 9; `az-rest` remains the
sole CI witness for 10, down from 18, and four of those are surfaces Microsoft
ships no client for.
[**Correction — both counts above are wrong**, and neither described the tree
at any point. Counted from `docs/witnesses.json` at `81b840fd^` and
`81b840fd`: `ci:fabric-cli` goes from 3 claims to **8**, not 9, which is also
what #499's own commit message says. And `az-rest` goes from **14** sole CI
witnesses to 10, not from 18 — **18 is its TOTAL citations**, a different
measure that this release did not change and that is still 18 today. The two
were conflated when this was written. The shape of the claim holds: typed
verbs took four claims off `az-rest`'s sole-witness count and `fab` gained
five.]

**A gap this found and did not fill:** `provisionIdentity` starts its LRO with
an empty result reference, so the operation completes and
`/v1/operations/{id}/result` serves nothing. The provisioning is correct; the
document a caller reads it back from is missing. Asserted as refused so it
cannot close unnoticed.

## Checkers for things nothing read (#495, #498)

**Go comments** (#495). `check_doc_drift.py` holds prose to the tree and
`check_plan_freshness.py` holds a docs/24 row to its sub-plan; both stop at
`docs/`. A Go comment is where this repository keeps its reasoning, and
nothing read one — #490 retired the connector-leaf justification and two
source comments went on teaching it in the present tense for a week.
`check_comment_drift.py` asserts repo-rooted paths and `docs/NN` references
resolve, and pins retired vocabulary so it cannot creep back.

**Two gates in `make check` had no tests at all** (#498).
`check_endpoint_env_names.py` and `check_mlflow_unpublished.py` both measured
0.00% covered. The second is the ONLY thing asserting the mitigation for
GHSA-h7x2-h6g9-p789, an advisory with no fixed release: a regex that stopped
matching would have reported "publishes no host port" about a stack that
published one.

## Upgrading

- **`note` on a deployment operation is an object.** It was a string; it is
  now `{"content": "…"}`, which is the documented
  `DeploymentPipelineOperationNote`. A consumer reading it as a string breaks.
- **`performedBy` on a deployment operation is a principal object**, not a
  bare id: `{"id": …, "type": …}`.
- **Domain role assignments report `Admin` and `Contributor`**, not `Admins`
  and `Contributors`. Both spellings are still ACCEPTED on input, so only a
  consumer reading the response is affected.
- **An unrouted `/v1.0/myorg` path answers a JSON 404** in Power BI's envelope
  (`{"Message": …}`) rather than the portal's HTML. A client that was
  string-matching the HTML will not find it.
- **Create Deployment Pipeline answers with `stages`**, and operations now
  carry `type`, `status` and `lastUpdatedTime`. Additive, but a strict
  deserialiser that rejects unknown fields will see them.

`FABRIC_RECORD_RESPONSES` is off unless set, and records no headers when it
is. Consumers pin by digest, so bump `FABRIC_EMULATOR_VERSION` and
`FABRIC_EMULATOR_DIGEST` together.
