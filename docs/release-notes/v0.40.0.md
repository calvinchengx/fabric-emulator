# v0.40.0

The range starts at `0bbf2c08` (#513), the first commit after the `v0.39.0`
tag, and ends at `7dba97a4 (#520)`: 7 changes. #518 landed inside #519 rather than on
its own.

The headline is **the measurements got correct, and then the evidence caught up
with them.** Route coverage goes from 86/167 to **116/172**, and the surface
ledger's *served* count goes from 120 to **422**. Read those two numbers
differently, because they are not the same kind of improvement:

- **The ledger's 302 extra served operations are not new capability.** This
  emulator was serving them all along. The parser that lists its routes could not
  see them, so the ledger reported operations as "nothing has ever asked" that
  the emulator answers.
- **Route coverage's +30 splits 23 / 7.** Twenty-three are routes a real client
  now demonstrably reaches (#513 +8, #517 +10, #519 +5). Seven are routes that
  were already being driven and that the parser could not see or match
  (#514 +5, #515 +2).

**Read Upgrading before you bump.** One response shape changes, and a new gate
can fail a build that the previous release passed.

---

## The measurement that declined 28 suites was short by 34 routes (#513)

"Measure first, then decide" produced the wrong answer, because the route
ratchet could not see 34 of its own routes at the time, and those were exactly
the prefix-loop registrations that Livy, materialized lake views, shortcuts,
triggers and the Airflow files API use. Suites were graded "adds nothing" when
their routes were invisible to the grader. With the denominator honest the
measurement was redone by scoring each suite's *marginal* contribution over the
existing union: `e2e/livy` +6 and `e2e/sail` +2 were kept, `e2e/environment` +0
and `e2e/airflow` +1 reverted. One route does not justify a `needs:` entry,
because an absent recording takes the conformance gate red for a reason that is
not its own.

**Both new suites recorded nothing in CI and passed anyway.** The emulator image
is distroless `:nonroot` and a bind mount owned by the runner cannot be written
by it; recording is never fatal by design, so the suites went green having
recorded nothing, and the ratchet then blamed eight routes. macOS bind mounts are
permissive about uid, so no local run showed it. The aggregate job now asserts
every expected recording **by name** and fails naming the suite that went quiet.

## 909 registrations were invisible, and the guard against that stayed quiet (#514)

The previous release taught the route parser to resolve a pattern assembled from
a variable and said anything it still could not resolve would fail the run. That
premise was false, because **a partial match reads as success**:
`"GET /v1/workspaces/{wid}/"+collection` matched its prefix, produced a truncated
route, and counted as resolved. Four fictional routes entered the denominator and
909 real ones never did. The 51 typed item collections are now treated as an
*alias family* — expanded to their real names for matching and collapsed to one
label for counting, since 459 rows of one handler would be a baseline nobody
reads. Collapsing folds by **provenance, not spelling**: `sqlEndpoints` is itself
a typed collection, and folding by name claimed all 51 answer `refreshMetadata`.

## A recorded response the parser cannot explain is a parser bug (#515)

Every response a recording holds was routed by this emulator's own mux, so if the
parser can explain none of it, the parser is wrong — not the traffic.
`orphaned()` checks exactly that, and **found a real bug the day it was written**:
Go's `{name...}` wildcard matches the rest of the path including slashes, and the
matcher treated it as a single segment. 95 recorded responses, almost all of them
Livy Statements calls, matched nothing. `GET` and `DELETE` on the Livy passthrough sat in the baseline as
unexercised while every run of that suite drove them.

## Two suites that already drove ten uncovered routes now record them (#517)

`e2e/data-science-loop` (+6: the tenant scanner, `admin/workspaces/modified`, the
group-scoped dataset refresh history) and `e2e/eventstream` (+4: reflex triggers,
eventstream destinations, source events) were kept; `e2e/notebook-run` +1 and
`e2e/deployment-pipelines` +0 were reverted. **The eventstream baseline is the
Sail engine's**, because CI runs Sail and the two engines credit different routes.

New traffic found a new disagreement, pinned rather than fixed: five
Reflex-triggered runs report `invokeType: "EventTriggered"`, outside Microsoft's
enum of `Scheduled` and `Manual`. It is the emulator's own distinction between a
job an Activator trigger started and one a person did, five e2e assertions depend
on it, and what real Fabric reports cannot be settled without a tenant.

## Five more routes are driven, and Move Item now answers what Microsoft documents (#519)

`e2e/fabric-cli` gains `job start` / `run-status` / `run-cancel` (typed fab verbs,
reaching the cancel route and the job-instance read) and a `fab api` passthrough
for `PATCH /items/{id}`, `…/move` and `bulkMove`. The passthrough is a transport
and is credited no higher than `az rest`. The instance is already terminal when it
is cancelled, so this witnesses the routes and fab's parse of each reply, **not
cancellation semantics.**

**`fab mv` is not the client for those routes.** In the locked fab (1.2.0) an item
move is `getDefinition`, a create and a delete — a copy — and never a `PATCH`. An
earlier draft trusted a newer release's source, passed for the wrong reason (a
client-side cache reported a rename the server never made), and was corrected by
the recording, which holds the server's own answers.

**Move Item answered a bare item** where Microsoft documents `{"value": [Item]}`,
found by conformance the first time a recording reached the route. `fabric-cicd`
calls it on a redeploy and stores the response without reading a field, so that
witness is unaffected.

**A limit a real client found.** `fab acl ls <item>` reads the admin item-users
list and fails inside fab on `principal.displayName`. Microsoft's spec marks that
field optional and fab evidently relies on real Fabric sending it (unconfirmed
without a tenant); this emulator has no directory to source a name from and omits
what it cannot source rather than inventing it. The response is spec-conformant
and unusable by Microsoft's own client, asserted as a failure so it cannot close
unnoticed.

## A route no spec documents is the direction that bites hardest (#518)

Three gates read the vendored swagger from three angles, and all of them point from
the spec, or from what is registered, towards evidence. None asked the inverse:
**which routes does this emulator answer that no published spec describes?** That
is the worse direction — a script written against the emulator passes, ships, and
404s against real Fabric. `check_undocumented_routes.py` classifies all 613
registered in-scope routes: 422 documented, 148 typed-collection aliases, 37
declared emulator-native *each with a written reason*, and **6 undocumented**,
each recorded with what was checked. It ratchets in both directions and, unlike
its siblings, needs no recording, so it runs in `make check`.

Two things in it worth knowing. The alias rule is derived from source rather than
guessed, because a looser "swap any segment for `items`" credited emulator-native
`POST …/lineage` as a documented Fabric operation. And one of the six is a real
finding kept visible rather than matched away: the vendored swagger spells Run
On-Demand Item Job with `jobType` as a **path** parameter
(`/jobs/{jobType}/instances`), while this emulator serves `/jobs/instances?jobType=`
— the form Microsoft's own `fab` records against it.

**It also fixed a defect in #514's parser.** `alias_values()` read map keys out of
raw source and could not tell code from prose, so a comment that *quoted* a payload
— `"type": "CopyJob"` — invented a `type` collection and, through
`registerTypedCollection`, nine routes nothing registers. The collapsed coverage
counts never moved, but the new baseline would have recorded nine fictions as
adjudicated surface. Line comments are now stripped before keys are harvested.

## The Homebrew cask no longer uses a deprecated stanza (#516, #520)

`hooks.post.install` renders as `postflight do`, which Homebrew now warns about on
every command. The quarantine-clearing step is carried as `postflight_steps`
through `custom_block` instead, and `check_cask_stanzas.py` checks both the config
and the cask GoReleaser actually rendered. Homebrew users should stop seeing the
deprecation warning once this release's cask reaches the tap (not yet observed);
the step that lets the unsigned binary run without a Gatekeeper prompt is
preserved.

**The check was first written into the wrong job** — the Docker-image job, before
checkout, on a different runner from the one GoReleaser writes the cask on — and
would have failed that job on the first tag ahead of the image push. Nothing on a
pull request runs `release.yml`, so it sat on `main` (#520). It was proven before
shipping by rendering a real cask with a GoReleaser snapshot. **This release is the
first real run of that step**; if its cask check goes red, the cask was still
published, because it runs after the push.

## Upgrading

- **`POST /v1/workspaces/{id}/items/{id}/move` answers `{"value": [Item]}`**, not
  the bare item. A consumer reading `id` or `folderId` from the top level will not
  find them; read `value[0]`. Its status and what the store holds are unchanged.
- **`make check` can now fail a build the previous release passed.**
  `check_undocumented_routes.py --strict` runs in it: registering a route that no
  spec documents, and that is not declared emulator-native with a reason, fails.
  So does removing a route that the baseline still lists.
- **The route ratchet fails on unexplained traffic.** A recorded non-404 response
  that no registered template accounts for is reported as a parser defect and stops
  the run, whether or not `--strict` is set.
- **Four e2e suites gain recording** when `FABRIC_RECORD_RESPONSES` is set —
  `livy` and `sail` (#513), `eventstream` and `data-science-loop` (#517). Off
  unless set, and no headers are written when it is.

Consumers pin by digest, so bump `FABRIC_EMULATOR_VERSION` and
`FABRIC_EMULATOR_DIGEST` together.
